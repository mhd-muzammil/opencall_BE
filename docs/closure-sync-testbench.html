What the real data proved

findings that changed the plan

1. Cancelled work orders carry no closure date. 9 of 74 rows are Closed - Canceled with Closure Date = NULL. The current parser counts them as skippedNoDate and throws them away — but Flex considers them closed. The column closure_date DATE NOT NULL in migration 029 physically cannot store them. This is a schema change the plan did not have.

2. The status string contains both words. "Closed - Canceled" matches CLOSED and CANCEL. Check order is load-bearing — classifyRawStatus already tests CANCEL first, so copy that order rather than writing a fresh matcher.

3. Zero WO overlap between 30-Jul and 31-Jul. Which makes the delete-everything import maximally destructive: importing 31-Jul over 30-Jul takes the table from 48 rows to 13 and loses every previous closure.

4. Closure day always equals activity day across all 74 rows — so a "today" filter on activity does return today's closures. Worth asserting, because the whole hourly design rests on it.
